# Experiment suite and results

Everything below is generated by `python experiments.py --suite all --out results && python analyze.py results`
(about 2 minutes). Full tables: `results/SUMMARY.md`; raw per-run data: `results/*.csv`;
provenance: `results/*.manifest.json`; figures: `results/fig_*.png`.

## Method (how the study is controlled)

* **Workloads** (all functionally verified at the reversible level for adder/multiplier, Toffoli verified against the exact CCX unitary):
  `adder_small` (adder4, 10 q), `adder_large` (adder16, 34 q), `multiplier` (5-bit schoolbook, 26 q),
  `qft` (16 q, approximate QFT cutoff 6, rz cost model), `high_parallel` (6 interleaved 4-bit adders, 60 q).
  Seeded random Clifford+T circuits (seeds 0–4) are used for variability.
* **Architecture** per configuration is built once and shared by all policies (fingerprints asserted equal):
  Line-SAM banks of ~square shape, one bus lane per bank, `max_parallel_ops=4`, d=11, `Timing.lsqca_paper`.
* **Sweeps:** CR ∈ {2,4}, banks ∈ {1,2,4}; magic states finite (15 beats/state) vs unlimited (isolates memory effects);
  baseline prefetch window W ∈ {1,2,4,8} (CR ∈ {4,8}); factory interval ∈ {1,2,4,8,15}.
* **Integrity:** each run is executed twice (schedule hash must match) and validated by the independent checker;
  CSVs contain no wall-clock data and are byte-reproducible.
* **Baseline strength:** "best fixed" = per-configuration *oracle* minimum over demand/prefetch × LRU/Belady (W=4).
  This is deliberately conservative for the DAG scheduler.

## Results (150 configurations x policies; see SUMMARY.md for every number)

Speedup = best-fixed cycles / best-DAG cycles (geomean over CR × banks).

| workload | finite magic (15 b/state) | unlimited magic |
|---|---|---|
| adder_small | 1.00 | 1.05 |
| adder_large | 1.00 | 1.04 |
| multiplier | 1.00 | 1.05 |
| qft | 1.00 | 1.62 |
| high_parallel | 1.34 | 1.85 |
| **all 30 configs** | **1.06** | **1.28** |

1. **With the paper's single 15-beat factory, scheduling barely matters** for adder/multiplier/QFT (all policies within ~0.1 %):
   execution is magic-state-bound, which is exactly the regime where [LSQCA] argues memory latency is hidden. Memory
   scheduling only matters there when the fixed-order policy *delays T issue* (high_parallel: up to 1.57x).
2. **When magic states are not the bottleneck, DAG-aware scheduling helps substantially where the DAG has parallelism**
   (QFT 1.6x, high_parallel 1.85x, CR=4: geomean 1.45x) because it overlaps independent work and transfers.
3. **Negative result — CR=2:** with no spare CR slots the DAG scheduler is up to ~10 % *slower* than the best fixed
   policy on serial arithmetic (multiplier unlimited: 0.90–0.91x; adders 0.98x). It loses on 8/30 unlimited configs.
   Diagnosis so far: it moves the scan line more (adder16: 148 vs 40 shift beats) and shows extra idle gaps that transfer
   time alone does not explain; a locality tie-break (`crit_tol`) did not fix demand-only mode. **Open issue.**
4. **Policies are provably identical at CR=2 for the fixed-order family** (head op needs both slots: no prefetch room, no
   victim choice) — this explains the identical smoke-test results (`tests/test_simulator.py`). Fixed policies produce
   different schedules only with CR ≥ 3 or when ops share operands.
5. **Ablation:** speculative prefetch with eviction is the main contributor (W=0 → W≥2: 1.09 → 1.03 geomean slowdown vs
   the best variant); the prefetch window (2/4/8), eviction cost weight, and urgency metric matter little; allowing
   prefetch to evict is important (`noevict` ≈ no prefetch).
6. **Traffic:** DAG scheduling often issues *more* transfers on serial circuits (multiplier: ~2.4x, qft 2–3x) while being
   faster; on high_parallel it issues fewer (2194 → 776–954). Report both cycles and transfers.
7. **Seeds:** random circuits: DAG speedup 1.51–1.63 (mean 1.58, std 0.05); the simulator is deterministic, so variance
   comes only from the workload seed.

## Threats to validity (read before citing)

* Two Line-SAM constants (`port_move`, `line_shift`) and the CX/Pauli durations are assumptions (docs/ASSUMPTIONS.md).
* Workloads are small (≤ 60 logical qubits, ≤ 2.3 k ops); the paper's are 60–433 qubits. Scaling trends are untested.
* `qft` rotation cost uses a crude T-count model; the ranking of policies there depends on that count only weakly, but absolute cycles do.
* No conventional-floorplan baseline and no Point-SAM, so memory-density/overhead claims of [LSQCA] are not reproduced.
* The DAG scheduler is a heuristic first version; no optimality gap (e.g. vs an ILP/lower bound) is reported.
* Physical-qubit estimates use placeholder area constants.
